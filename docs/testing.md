# Testing

```sh
cmake --preset linux-debug
cmake --build --preset linux-debug
ctest --preset linux-debug                 # everything
ctest --preset linux-debug -L unit         # one suite: unit, integration, regression, ui, app
```

## Suites

| Label | Directory | What it covers |
|---|---|---|
| `unit` | `tests/unit` | Core types, checked arithmetic, file reading, hashing (NIST vectors), identification, PE header/import/export/overlay parsing, sections, strings, entropy, rules, scoring, reports, HTML escaping, batch export, history, reputation parsing/rate limiting/caching, signature handling |
| `integration` | `tests/integration` | The full engine on synthetic files, malformed headers, batches, YARA, file size and string limits, cancellation |
| `regression` | `tests/regression` | Hostile inputs run end to end through the engine and both report writers |
| `ui` | `tests/ui` | Models, panels, the analysis controller, settings, batch window, report export (runs with `QT_QPA_PLATFORM=offscreen`) |
| `app` | – | The application starts and exits cleanly |

Test files are generated by `tests/support/PeBuilder`, so no binaries, and no malware, are
checked in. Tests that need a malformed file build a valid one and overwrite fields.
`EngineSystemBinaries.ParsesWindowsBinaries` runs only on Windows, against binaries from
`System32`.

## Sanitizers

```sh
cmake --preset linux-sanitize
cmake --build --preset linux-sanitize
ctest --preset linux-sanitize
```

This builds everything, including LIEF, with AddressSanitizer and UndefinedBehaviorSanitizer and
stops on the first error.

## Fuzzing

```sh
CXX=clang++ cmake -B build/fuzz -G Ninja -DSECTORYN_BUILD_FUZZERS=ON -DSECTORYN_BUILD_APP=OFF
cmake --build build/fuzz
./build/fuzz/bin/fuzz_pe_parser -max_len=1048576 corpus/
```

`fuzz_pe_parser` runs bytes through the parser (with its validation) and section analysis;
`fuzz_strings` through the string extractor, in chunks of varying size, and the indicator
classifier. Neither touches the
disk. With GCC the harnesses are built as replay tools that run the files given on the command
line, to reproduce crashes found elsewhere.

Every crash fixed gets a test in `tests/regression`.

## Static analysis

`.clang-tidy` lists the enabled checks. The `static-analysis` workflow runs clang-tidy over
`compile_commands.json` and the sanitizer build on every push.
